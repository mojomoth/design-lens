# .agentdocs/ — the loop's source of truth

This directory steers the autonomous build. Read top-down: specs define WHAT, the plan defines
the ORDER, PROGRESS carries learnings between fresh-context iterations, DECISIONS records why.

| File | Role |
|---|---|
| `specs/*.md` | One topic of concern each. The product truth. |
| `ARCHITECTURE.md` | Intended system shape: modules, data flow, packaging. |
| `ACCEPTANCE.md` | Human-readable mirror of the sealed machine gate (`.harness/verify.sh --strict`). Editing this file changes nothing — the machine gate is sealed. |
| `CONVENTIONS.md` | Code style, dependency allowlist, commit format, test rules. |
| `DECISIONS.md` | ADR log. Seeded ADR-001…ADR-009 are append-only. |
| `IMPLEMENTATION_PLAN.md` | GENERATED by `ralph.sh plan`. Disposable — regenerate when stale. |
| `PROGRESS.md` | Append-only iteration learnings + pinned codebase patterns. |

## Write-permission matrix (enforced by `.harness/verify.sh` and `ralph.sh`)

| Path | Plan loop | Build loop | Enforcement |
|---|---|---|---|
| `.harness/**` | read-only | read-only | sha256 seal (in-repo + out-of-repo copy) checked every iteration; violation ⇒ restore from `bootstrap` tag + abort |
| `specs/**`, `ARCHITECTURE.md`, `ACCEPTANCE.md`, `CONVENTIONS.md` | writable | **spec-drift protocol only** | after the `plan-complete` tag exists, any content drift in these files requires: (a) more ADRs than the 9 seeded ones, and (b) every drifted file's basename mentioned in `DECISIONS.md` |
| `DECISIONS.md` | append | append | all seeded ADR ids must keep existing (append-only ratchet) |
| `IMPLEMENTATION_PLAN.md`, `PROGRESS.md` | writable | writable | plan grammar is machine-linted (`verify.sh --plan`) |
| `AGENTS.md` | writable | writable (sparingly) | keep < 60 lines, operational facts only |
| `plugin/**` | **read-only** | writable | plan-mode iterations that write outside `.agentdocs/`+`AGENTS.md` are hard-reset |

## The canonical contract (names that must never diverge)

- Plugin root: `plugin/` — marketplace sources point at `./plugin`.
- CLI package: `plugin/cli/` (self-contained; NO npm workspaces). Committed bundle:
  `plugin/cli/dist/design-lens.cjs` (+ committed `package-lock.json`).
- npm scripts in `plugin/cli/package.json` (load-bearing — the sealed gate calls them):
  `typecheck`, `test` (unit), `e2e`, `build`, `verify`.
- Skills (exactly five): `clone-reference`, `reverse-design`, `inspect-elements`,
  `customize-clone`, `build-from-design` under `plugin/skills/<name>/SKILL.md`.
- Runtime home: `~/.design-lens/` with launcher `~/.design-lens/bin/design-lens` — the ONLY
  executable path skills may reference.
- Clone output: `.design-lens/<slug>/` in the user's project (see specs/03-clone-format.md).
- CLI I/O: human progress → stderr; machine output (JSON) → stdout; exit 0 success / 1 fatal.
