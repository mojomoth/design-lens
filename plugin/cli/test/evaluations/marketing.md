# Brief: Relay Desk product introduction

Build a new responsive product introduction page for **Relay Desk**, using the provided local
reference as design research. This is a complete build request, including analysis and verification.
No existing project, assets or chosen variation: choose the direction that fits this brief.

Audience: small service teams handing customer work between shifts. Primary task: understand the
offer and try a clearly labeled local demo. Use original text and system fonts; no external assets.

Content to include (you may edit connective prose, preserving these facts):
- Headline: **A clear handoff. A calmer next shift.**
- One-liner: Relay Desk keeps the next action, owner, and context together for small service teams.
- Benefits: **One next action** — leave the next teammate a concrete step; **Context that travels**
  — keep the customer story with the work; **A visible owner** — know who is taking it forward.
- Process: **Capture the context → Name the next action → Hand it over.**
- Access section: **Explore the local demo**. This prototype has no account service or paid plan.
  No prices, customer logos, testimonials or performance claims may be invented.
- Navigation must reach real sections. Primary CTA: **Try a handoff**, opening or scrolling to
  the demo form. Form fields: work subject (required), next action (required), owner (required).
  Submit action: **Preview handoff**. Validate required fields and show a visible confirmation
  containing the entered values, labeled **Local demo — nothing was sent or saved**. Allow
  another preview. This is intentionally local behavior, without a backend.
- Footer: Relay Desk / A local product prototype.

Verify 1440×900, 768×1024 and 390×844, a long subject, keyboard focus, navigation, blank-form
validation and successful preview. Keep DESIGN.md/VARIATIONS.md and distinct verification images.
