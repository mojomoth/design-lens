# Design Lens 0.2.0

Design Lens now connects reference capture and measured design evidence to a frontend adapted
to the user's product, with implementation and responsive/behavioral verification.

## Changes

- `inspect --viewport WxH` measures responsive layouts. Default output remains compatible;
  role classification excludes hidden candidates.
- `inspect --details` adds computed typography, spacing, borders, grid/flex layout, element
  relationships, selected images, root/body measurements and font readiness.
- `inspect --id dl-N` measures an individual light-DOM element, including hidden or unclassified
  containers. Invalid, missing and duplicate IDs produce explicit errors.
- Font readiness failures produce qualified evidence and screenshots without a second implicit
  font wait. Normal image/style loading, requested dimensions and pixel density are preserved.
- Reverse design separates reference observations, clone measurements, inferences, proposals
  and unavailable evidence. The twelve-section analysis leads to three adaptable directions.
- New-page requests continue through context discovery, structural adaptation, implementation,
  viewed desktop/tablet/mobile images and actual interaction checks. Capture-only and
  analysis-only requests end at their requested output.

## Install

Claude Code:

```bash
claude plugin marketplace add mojomoth/design-lens
claude plugin install design-lens@design-lens
```

Codex CLI:

```bash
codex plugin marketplace add https://github.com/mojomoth/design-lens
codex plugin add design-lens@design-lens
```

In Codex, trust the plugin's SessionStart hook with `/hooks`, or provision the runtime manually:

```bash
npx -y design-lens@0.2.0 setup
~/.design-lens/bin/design-lens --version
```

For Cursor/OpenCode and other supported agents, install the skills with
`npx skills add mojomoth/design-lens`, then run the same setup command. The npm package provides
the CLI; agent skills generate the design documents and application code.

See the [Korean usage guide](https://github.com/mojomoth/design-lens/blob/v0.2.0/docs/USAGE.ko.md)
for update instructions and complete prompts, or the
[English plugin guide](https://github.com/mojomoth/design-lens/blob/v0.2.0/plugin/README.md).

## Validation and scope

The release implementation passed `bash .harness/verify.sh --strict`: 454 unit tests, 117 E2E
tests, sealed fixture spine/full-fidelity checks, plugin validation and reproducible bundle/version
checks. The npm tarball was extracted and its actual runtime setup and CLI were checked separately.

Two fresh-agent evaluations adapted one local reference into a product introduction and a dense
management screen. Independent review covered all three viewports and working controls. See
[recorded results and limits](https://github.com/mojomoth/design-lens/blob/v0.2.0/plugin/cli/test/evaluations/RESULTS.md).

Verification used local Chromium and loopback fixtures. Structural `verify` results do not certify
visual quality. Clones remain private study material; new products use the user's content/assets.
