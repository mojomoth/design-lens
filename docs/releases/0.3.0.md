# Design Lens 0.3.0

**Release prepared locally.** These notes describe the implementation in this checkout. They do
not assert that a 0.3.0 package, tag or GitHub release has been published.

## Faithful static capture

The clone skill captures one public page at **1440×900, 768×1024 and 390×844** by default. It
reloads the original for each size and preserves separate source DOM, assets, observations,
screenshots and capture conditions. The first capture supplies one editable HTML/CSS clone
that is tested at all captured sizes. Direct CLI use retains the single 1440×900 default;
request several sizes with `--viewports WxH,...`, separately from `--viewport`.

Asset discovery and rewriting share one traversal for HTML, CSS, SVG and nested documents. It
handles document bases, redirected stylesheet bases, SVG fragments, CSS custom-property URLs,
image-set sources and preloads. Rewritten integrity and content-security restrictions are removed.
Accessible iframe and srcdoc content is recursively preserved as inert static markup. Content
variants receive distinct asset paths so one capture cannot overwrite another's resource.
Accessible frames still report `unverified` because child semantic measurements are not yet
frame-scoped; static preservation alone does not certify every embedded element.

Original scripts and event handlers are removed. The result captures static appearance, not
the source application's JavaScript behavior. Missing embeds, closed shadow roots, unavailable
fonts or images, and capture limits remain visible in the evidence and result.

## Measured comparison and bounded repair

```bash
~/.design-lens/bin/design-lens clone https://example.com --viewports 1440x900,768x1024,390x844
~/.design-lens/bin/design-lens fidelity .design-lens/example-com --json
```

Use the actual `projectDir` returned by clone in place of the example path. Fidelity renders the
current clone with external requests blocked and compares saved source images and measurements.
Its fixed policy uses pixelmatch threshold 0.1 with antialiasing differences excluded, at most
0.5% mismatch per image, at most 1% per major region, and at most 1 CSS px difference in major
element position or size. Image-size differences and missing required elements, fonts or images
prevent a pass. Incomplete source evidence cannot be averaged into a passing score.

`pass` exits 0. `fail` and `unverified` exit 1. The report covers recorded static states only;
it does not certify every possible viewport or interactive state. `verify` continues to check
the existing clone format independently of visual comparison.

The CLI measures and diagnoses. The clone skill can repair assets, HTML and CSS for at most
three rounds, checking every captured size after each round. It stops when improvement stops,
restores the best candidate and reports unresolved differences. It preserves source evidence
and IDs, and does not replace the page with an image, mask differences or loosen thresholds.
Customization follows the user's requested changes and reports intentional differences instead
of undoing them to satisfy source fidelity.

## Immutable evidence and compatibility

`evidence.json` and `evidence/` contain source records and hashes. Treat them as immutable, not
as editor state. Observation IDs are scoped to each capture: equal `dl-N` strings in different
captures do not establish element identity. `fidelity.json` binds comparison results to both
source evidence and the current clone files. Rerun fidelity after edits.

Existing clones still open and can be edited. Without original capture evidence, visual
verification is `unverified`; any required recapture goes into a new project. Legacy evidence
must not be invented from the current clone.

## Implementation-ready reverse engineering

`inspect --all --details` measures all stamped elements, including body content, cards, forms,
tables, containers and open Shadow DOM. Repeat `--id` to inspect several elements. Detailed
output includes typography, layout, parent/child relationships, pseudo-elements, backgrounds,
gradients, image cropping and font state. Closed roots remain unavailable. These are observations
of the current clone, distinct from preserved original observations.

`tokens.json` moves to **schema version 2**. Colors preserve alpha in `alpha`, `css` and `oklch`,
and transparent colors do not become representative colors. Font shorthand and selector targets
are interpreted more accurately. `calc()` operands are not independent spacing values. Without
support for a 4px or 8px grid, `spacing.base` is `null`; unsupported values are not snapped to an
invented grid. Consumers must handle nullable bases and alpha-preserving colors.

Token provenance records CSS sources and hashes, including inline styles, unresolved declarations,
warnings and unit assumptions. CSS declaration statistics are not measurements of rendered area
or original design intent. Static rem/em conversion uses a documented 16px assumption; use the
observed values when writing design recipes.

`DESIGN.md` retains its twelve sections and adds layout, typography, color, spacing, component
and responsive recipes, a CSS example, and a measured-observations table. The required columns are
`Label`, `Capture`, `Viewport`, `Observation`, `Field`, `Value`, `Unit` and `Precision`. Source
and clone observations are separate; unavailable evidence, inferred intent and proposed behavior
must remain explicit. `VARIATIONS.md` grounds three directions in those rules without inventing
requirements for an unspecified target product.

```bash
~/.design-lens/bin/design-lens inspect .design-lens/example-com --all --details --viewport 390x844
~/.design-lens/bin/design-lens inspect .design-lens/example-com --id dl-17 --id dl-18
~/.design-lens/bin/design-lens validate-design .design-lens/example-com --json
```

`validate-design` is read-only. It checks required document tables, capture/observation references,
evidence hashes, values, units and rounding. Numeric units are px, rem and unitless with precision
0–6; px/rem conversion uses the observed root font size. CSS strings and alpha-aware colors use
precision `-`. Clone claims need a current hash-bound fidelity report. Only `pass` exits 0;
`fail` and `unverified` exit 1. Structural and numeric validation does not validate interpretations
of design intent or a new implementation's behavior; independent implementation and rendered
review remain necessary.
